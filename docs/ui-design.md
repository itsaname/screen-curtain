## 0. 结论摘要

### 0.1 目标界面形态

幕帘是一个**低干扰的常驻托盘工具**，完整界面由 7 个表面组成：

| 表面 | 作用 | 是否常驻 |
|---|---|---|
| 首次运行向导 | 解释黑屏/更新保护风险，取得同意，完成 UAC | 首次运行 |
| 主窗口 | 熄屏入口、显示器状态、更新保护状态、快速选项 | 是 |
| 设置窗口 | 启动、熄屏、更新保护、诊断与关于 | 按需 |
| 托盘图标与菜单 | 快速打开/熄屏/恢复/退出 | 是 |
| 确认对话框 | 退出、恢复失败、关闭保护等高风险操作 | 按需 |
| 通知 | 最小化、保护降级、恢复失败 | 按需 |
| 熄屏状态 | 所有显示器全黑，无任何应用 UI | 熄屏期间 |

### 0.2 关键 UI 决策

1. **主窗口是控制中心，不把设置堆在主界面上**：常用动作和状态在一屏内完成，完整设置放入独立模态窗口。
2. **首次运行分 3 步向导**：先讲清限制，再选择是否启用更新保护并触发 UAC，最后设置热键，避免首次启动直接弹 UAC。
3. **更新保护期间主窗口不隐藏到托盘**：允许最小化到任务栏，以保证关机否决所需的可见顶层窗口。关闭按钮在保护期间只最小化。
4. **熄屏期间不显示任何提示、倒计时或按钮**：纯黑覆盖全部显示器；鼠标移动不退出，点击/按键恢复。
5. **无边框全屏覆盖任务栏和通知区域**：不隐藏 `NotifyIcon`，托盘图标由全屏层自然遮挡；恢复后无重新出现的闪烁。
6. **黑屏期间应用弹窗/气泡全部静默**，Topmost Guard 尝试压住第三方提醒；安全桌面例外。
7. **黑屏默认静音系统播放设备**，恢复时还原原静音状态；可在设置/快速选项关闭。
5. **所有危险/失败状态都必须有下一步动作**：UAC 取消、策略恢复失败、热键冲突、显示枚举失败都不能只显示错误文字。
6. **默认轻量、可回退**：设置自动保存；所有更新策略在退出时恢复；不显示虚假的“绝对保护”。
7. **首版采用浅色 Fluent 风格，标准 Windows 标题栏；深色主题、开机自启作为后续阶段**，中英文界面已实现，本文给出完整设计以便一次定稿。

## 1. 设计目标与原则

### 1.1 目标

- **一眼看懂当前状态**：是否已熄屏、几台显示器、更新保护是否开启、为什么降级。
- **最短路径熄屏**：启动后一次点击，或直接按全局热键。
- **绝不把用户困在黑屏或锁屏后**：任何键鼠输入都能恢复；会话锁定/断开自动恢复。
- **对系统修改透明**：启用更新保护前明确说明需要管理员权限、会临时暂停自动更新、退出时恢复。
- **可访问**：完整键盘操作、屏幕阅读器标签、高对比度、100%–200% DPI。
- **可维护**：主窗口不承载所有逻辑；状态通过 Presenter 驱动，便于测试。

### 1.2 非目标

- 不做锁屏、密码验证或家长控制。黑屏不是锁屏。
- 不永久关闭 Windows Update，不删除待重启标记。
- 不阻止用户主动关机/重启；只阻止本程序运行期间的更新重启尝试，并允许用户退出后重启。
- 不做游戏内叠加层、远程控制、云同步或遥测。
- 不隐藏系统 UAC、安全桌面或强制关机界面。
- 首版不承诺“100% 拦截强制重启”。

### 1.3 体验指标

| 指标 | 目标 |
|---|---|
| 正常启动到主窗口可用 | ≤ 1.5 s（不含 UAC 用户操作） |
| 点击“立即熄屏”到覆盖层出现 | ≤ 500 ms |
| 点击/按键到桌面恢复 | ≤ 500 ms（不含显示器硬件唤醒） |
| 首次运行完成 | ≤ 3 个步骤，且不要求阅读隐藏说明 |
| 错误状态可行动率 | 100%（每个错误至少一个“重试/退出/日志/设置”动作） |
| 100% 键盘可达 | 主窗口、向导、设置、托盘菜单均可不用鼠标完成 |

## 2. 用户与使用场景

**主要用户**：在 Windows 11 桌面/笔记本上希望暂时关闭全部显示器，同时不希望 Windows Update 在任务期间自动重启的个人用户。

| 场景 | 用户目标 | UI 要点 |
|---|---|---|
| 夜间下载/渲染/长任务 | 屏幕全黑，任务不中断，更新不重启 | 更新保护状态突出；熄屏后无 UI |
| 会议/演示间隙 | 一键让所有显示器黑掉 | 大按钮 + 全局热键；不误触桌面 |
| 多显示器办公 | 主屏、副屏、竖屏同时黑 | 显示“覆盖 N 台显示器”；失败时明确提示 |
| 离开座位片刻 | 不需要锁屏，回来点击/按键继续 | 黑屏不等于锁屏警告；保持会话解锁 |
| 第一次使用 | 知道 UAC、自动更新暂停、如何退出 | 3 步向导；限制在启用前展示 |
| UAC 被拒绝 | 仍能熄屏，但不虚假显示“已保护” | 降级状态 + 重试 + 关闭保护 |
| 更新设置恢复失败 | 不丢失原始设置 | 危险横幅、重试、日志、退出警告 |
| 程序异常重启 | 无残留黑屏或策略 | 启动恢复提示；小黑屏覆盖窗口不残留 |

## 4. 启动与生命周期

### 4.1 启动模式

| 模式 | 触发 | 行为 |
|---|---|---|
| 首次运行 | 无有效设置或 `FirstRun=true` | 打开向导，不打开主窗口、不弹 UAC |
| 用户正常启动 | 用户双击 EXE/快捷方式 | 显示主窗口；若更新保护已启用则异步尝试启用 |
| 启动时最小化 | 设置 `StartMinimized=true` | 主窗口以最小化状态出现；UAC 仍可能弹出 |
| 第二实例 | 程序已在运行 | 将已有主窗口还原并置前；不创建第二个托盘图标 |
| 异常恢复启动 | 上次进程/系统异常结束 | 先提示/恢复遗留更新策略；恢复完成后进入主窗口 |
| 命令行启动 | 自动化/测试 | 不作为普通用户主路径；见设计文档 CLI |

首版**不做随 Windows 登录自启动**。原因：更新保护需要 UAC；用普通启动项启动会在登录时弹 UAC，用最高权限计划任务又会让整个 UI 高完整性运行，二者都不理想。若后续实现，应单独设计“计划任务启动守护/服务模式”，不应简单加一个 Run 键（见 §13 待确认）。

### 4.2 正常启动时序

```text
t0  进程启动，启用 Per-Monitor V2 DPI
t0  单实例检查
     ├─ 已运行：激活已有窗口，退出
     └─ 未运行：继续
t0  读取 settings.ini
     ├─ 损坏：使用默认值，主窗口显示“设置已重置”横幅
     └─ 正常：继续
t0  初始化托盘、主窗口
t0  首次运行? ── 是 ──► 向导（不 UAC）
     │
     否
     ▼
t0  显示主窗口（或最小化）
t0  更新保护已启用? ── 否 ──► 主窗口 UI-12
     │
     是
     ▼
t0  主窗口先显示“保护启动中”，异步启动辅助进程
     ├─ UAC 被拒绝：保护降级，主窗口 UI-11，不弹额外对话框
     ├─ 辅助进程失败：降级，显示原因和“重试”
     └─ 成功：保护开启，主窗口 UI-10
```

关键规则：

- **启动顺序不能阻塞 UI**：设置读取、日志、更新保护握手都在后台完成；主窗口先出现。
- **UAC 不在首次运行向导之外自动弹出**；用户必须先在向导点击“启用并继续”。
- 已有窗口的最小化状态可以在第二实例启动时恢复。
- 若上次有遗留策略快照，辅助进程先恢复再重新建立快照；主窗口保护卡片显示“正在恢复上次设置…”。

### 4.3 关闭、最小化与退出

| 用户动作 | 保护开启 | 保护关闭 |
|---|---|---|
| 点击窗口 X | 取消关闭，最小化到任务栏；托盘通知说明保护继续 | 按 `CloseAction`：默认最小化到任务栏；可选退出 |
| 点击最小化 | 最小化到任务栏，主窗口仍可见于任务栏 | 同左 |
| 托盘“打开幕帘” | 还原主窗口并置前 | 同左 |
| 主窗口“退出并恢复设置…” | 弹出退出确认，说明会恢复更新设置 | 确认后退出（无策略恢复需求） |
| 托盘“退出并恢复系统设置…” | 同主窗口退出 | 同左 |
| 熄屏期间 | 应用 UI 被覆盖；任何点击/按键恢复后回到主窗口 | 同左 |
| Windows 注销/关机 | 注销允许；重启/关机尝试被阻止，用户可从系统 UI 选择继续 | 不阻止 |

**保护期间绝不隐藏到通知区域。** 托盘图标可以提供快捷入口，但主窗口必须保留任务栏可见性，否则 Windows 可能不允许应用取消关机。若未来要支持“托盘模式”，必须先解决可见窗口要求（例如保留一个小型可见状态条）。

### 4.4 首次运行向导决策树

1. 显示向导 1/3（无 UAC、无主窗口）。
2. 用户必须勾选“我了解黑屏不是锁屏”才能进入下一步；否则“下一步”禁用。
3. 向导 2/3 选择“启用更新重启保护”或“仅使用熄屏”：
   - 启用：点击“启用并继续”后才触发 UAC。
   - UAC 取消：留在当前页，显示内联横幅“管理员权限请求已取消”，提供“重试”和“仅使用熄屏继续”。
   - 仅熄屏：直接进入下一步。
4. 向导 3/3 设置热键、是否启动后最小化；点击“完成”保存设置并进入主窗口。
5. 关闭向导（X/Esc 后确认）视为取消首次设置：不写入 `FirstRun=false`，下次继续显示向导；不修改注册表。

### 4.5 异常与恢复启动

- 若更新辅助进程发现遗留快照：在保护卡片上显示“正在恢复上次更新设置…”，恢复完成前不显示“已开启”。
- 若恢复失败：绝不覆盖外部策略；显示恢复失败卡片，提供“重试/打开日志/仍然退出（不推荐）”。
- 若上次熄屏状态异常：覆盖窗口随进程销毁；显示器可由输入唤醒；启动后主窗口提示“上次熄屏未正常结束”并提供日志。
- 若设置文件损坏：使用安全默认值、备份坏文件为 `settings.bad-<timestamp>.ini`，显示一次性横幅。

- “开始设置”在勾选前禁用；关闭窗口需二次确认“退出首次设置？”。

- 向导过程中若取消 UAC，用户可继续，不会被强制退出。

- 若第 2 步选择“仅熄屏”，摘要显示“更新重启保护：未启用（可稍后在设置中开启）”。
- “完成”后写设置、显示主窗口；不自动执行一次熄屏（避免用户未准备好时黑屏）。
- 若用户关闭向导：询问“退出首次设置？”，选择退出则不写 `FirstRun=false`。

| 保护降级 | “更新重启保护降级：{原因}。点击打开幕帘。” | 每次状态变为降级；不在熄屏时 |
| 恢复失败（熄屏后） | 恢复显示后再显示错误横幅/通知 | 不在黑屏时弹 |
| 显示器变化 | 不弹通知，主窗口数字更新 | — |
| 热键冲突 | 主窗口内联横幅，不弹模态 | 启动时 |
| 第二实例 | 激活已有窗口，不弹通知 | — |

- 使用 `NotifyIcon.ShowBalloonTip`；不引入额外通知依赖。
- 提供设置“显示托盘通知”开关；恢复失败不受开关限制。

### 5.6 熄屏状态（UI-50）

- 每台显示器一个纯黑、置顶、无边框、覆盖 `rcMonitor` 的窗口；覆盖任务栏和通知区域。
- 不隐藏 `NotifyIcon`；托盘图标由全屏层自然遮挡，恢复后仍是当前状态。
- 透明鼠标指针；不显示托盘提示。
- 鼠标移动不退出；鼠标按键、用户开启的滚轮或任意键盘按键恢复。
- 首个唤醒输入被吞掉，防止误操作。
- 黑屏期间本程序所有弹窗/气泡/通知静默，恢复后合并提示。
- Topmost Guard 使用事件钩子和短周期重新置顶压住普通第三方窗口/通知；安全桌面除外。
- **静音**：进入 Dark 后静音所有活动播放设备，恢复时还原每台设备原静音状态；新设备也会被处理。恢复在显示/黑层关闭之后执行，校验结果并延迟重试；锁屏后在解锁时重试。异常退出后下一次启动恢复。
- 物理关屏是尽力增强；不支持时仍保持全黑。
- 恢复后回到熄灭前的桌面；主窗口仍在任务栏/最小化，不强制置前。
- 安全桌面/独占全屏例外见 [设计文档 §5.9](design.md)。

### 6.3 控件状态

- 默认：表面色，1px 边框。
- Hover：加深/高亮，不改变布局。
- Focus：2px 强调色外环，始终可见。
- Pressed：轻微深色，不缩放。
- Disabled：降低对比度但保持可读；工具提示说明原因。
- Busy：按钮内显示“正在…”，禁止重复提交；不阻塞 UI。
- Error：InlineBanner + 字段边框/说明；不能只用红色。

### 6.4 热键录制

1. 点击录制框进入录制态，显示“请按下快捷键…”。
2. 用户按下组合键；只接受至少包含 Ctrl/Alt/Shift/Win 之一且包含非修饰键的组合。
3. 先尝试 `RegisterHotKey` 验证；失败则保持旧热键并显示“该组合已被其他程序占用，请换一个”。
4. 成功则立即保存并显示新热键。
5. Esc 取消录制，恢复原值；不保存。
6. 禁止 `Ctrl+Alt+Del`、`Ctrl+Shift+Esc`、`Alt+F4` 等系统/危险保留组合（给出提示）。

### 6.5 布局与 DPI

- WinForms 使用 `TableLayoutPanel`/`FlowLayoutPanel`，避免绝对坐标。
- 进程 Per-Monitor V2；主窗口/设置窗口 100%–200% 缩放；最小尺寸以 DIP 计。
- 文本换行，不使用固定高度裁切；设置页内容可滚动。
- 主窗口在启动它的显示器居中；用户移动后保留位置（可选）。
- 窗口使用标准 Windows 标题栏，保证 Snap、Alt+Space、辅助功能正常。

### 7.2 托盘与主窗口同步

- 所有保护状态变化由同一个 Presenter 驱动；托盘菜单和主窗口不能各自推断状态。
- 主窗口更新保护开关是“期望状态”，状态卡是“实际状态”；二者可以不同（例如期望开启但 UAC 被拒），UI 必须同时表达：
  - 开关：开；
  - 状态：降级；
  - 原因：UAC 取消；
  - 动作：重试 / 关闭保护。
- 避免“开关显示关但实际仍受保护”的状态。

### 7.3 导航规则

- 设置窗口是模态；打开后主窗口不可操作，避免状态并发。
- 向导期间不能打开设置。
- 熄屏期间不能打开任何应用窗口。
- 退出确认/恢复失败对话框为应用模态；UAC 为系统安全桌面。
- 第二实例只激活主窗口；不绕过熄屏的输入规则，不强制恢复显示。

## 9. 文案规范

### 9.1 术语

| 术语 | 使用规则 |
|---|---|
| 熄屏 | 用户动作/状态；包括全黑覆盖和尽力物理关屏 |
| 全黑 | 覆盖层保证的视觉效果 |
| 更新重启保护 | 本程序的更新策略+关机否决功能 |
| 降级 | 保护未完全生效，但仍尽力阻止；不要称“已保护” |
| 暂停自动更新 | 只在本程序运行期间，退出恢复；不要称“禁用更新” |
| 黑屏不是锁屏 | 首次运行和主窗口安全提示必须出现 |

### 9.2 关键文案

**主窗口副标题**
> 一键全黑；点击鼠标或按任意键恢复。

**保护卡（开启）**
> 已开启。运行期间临时暂停自动更新，并尝试阻止更新重启；退出程序时恢复。

**保护卡（降级）**
> 更新重启保护未完全生效。{原因}。Windows 更新仍可能重启系统。

**保护卡（未启用）**
> 未启用。建议开启，避免 Windows 自动更新在任务期间重启。

**首次运行限制**
> 黑屏不是锁屏。熄屏期间电脑保持唤醒，当前 Windows 会话保持解锁；任何能接触鼠标/键盘的人都可以唤醒电脑。

**首次运行更新保护**
> 启用后，程序运行期间会临时暂停 Windows 自动更新并阻止更新重启。这需要管理员权限；退出程序时恢复原设置。

**UAC 取消**
> 管理员权限请求已取消，更新保护未启用。你仍可使用熄屏功能。

**退出确认**
> 退出后将恢复 Windows Update 设置，并不再阻止更新重启。若正在执行任务，请先保存工作。

**恢复失败**
> 部分 Windows Update 设置未能恢复。备份已保留；请重试恢复或查看日志。

**热键冲突**
> 该组合键已被其他程序占用。请换一个组合，或使用默认热键。

**显示器失败**
> 无法读取显示器状态，已取消本次熄屏。请检查显示连接后重试。

## 10. 可访问性、主题与本地化

### 10.1 键盘

- 主窗口：Tab 顺序为 状态胶囊/设置 → 主按钮 → 显示器刷新/展开 → 保护详情 → 快速选项 → 底栏。
- Enter/Space 激活按钮；Space 切换开关；Esc 关闭设置/对话框（不关闭熄屏）。
- 向导：Tab 顺序按阅读顺序；Enter 主按钮；Backspace/上一步；Esc 需确认退出。
- 设置：Ctrl+Tab/左右键切换页面；Alt+Left/Right 可选；所有控件可达。
- 热键录制：Esc 取消，Enter 不提交（等待组合键）。
- 托盘菜单支持 Windows 键盘导航（Windows+B）。

### 10.2 屏幕阅读器

- 自定义卡片、状态点、开关设置 `AccessibleName`、`AccessibleRole`、`AccessibleDescription`。
- 状态变化通过 `AccessibleObject.NotifyClients` 或等价机制通知；不仅依赖颜色/动画。
- 状态文案同时表达状态与影响，例如“保护降级：管理员权限被取消”，不能只有“降级”。
- 关闭按钮可访问名称“关闭主窗口并最小化”，不是单纯“关闭”。

### 10.3 高对比度

- 检测系统高对比度，使用 SystemColors；禁用自定义浅色卡片背景和低对比度圆角。
- 焦点环、边框、状态点在高对比度下仍可辨。
- 不依赖颜色区分成功/警告/错误；使用文字/图标。

### 10.4 DPI/布局

- 100%、150%、200% 下无裁切；主窗口和设置支持滚动。
- 多显示器不同 DPI 时，窗口在当前显示器居中/保留位置。
- 最小点击目标 36×36，主按钮 44+；文本可换行。

### 10.5 主题

- 首版：浅色，跟随 Windows 强调色；标准标题栏。
- Phase 2：深色主题，使用 §6.1 的深色令牌；必须通过高对比度/焦点测试。

### 10.6 本地化

- 首版简体中文；所有 UI 字符串资源化，避免硬编码。
- Phase 2 英文；按钮宽度按最长文本预留，允许换行。
- 数字/文件路径使用系统区域格式；日志不带本地化歧义。

### 11.1 重构顺序

1. 抽取 `MainPresenter` 和 UI 状态模型，现有主窗口逻辑先不改行为。
2. 构建 `CardPanel`/`ToggleSwitch`/`StatusPill` 等基础控件与视觉令牌。
3. 重构主窗口为主设计稿，保留现有按钮/状态功能。
4. 加入设置窗口，迁移现有开关。
5. 加入首次运行向导和退出/恢复失败对话框。
6. 托盘/通知统一到 Presenter。
7. 可访问性、DPI、键盘测试。
8. 可选：浅色/深色主题、英文资源。

### 11.2 不改变的行为

- 全屏覆盖/物理关屏/输入钩子/会话安全/更新保护策略逻辑。
- 主窗口在保护期间不得隐藏到托盘（只最小化）。
- 首次运行不自动提权。
- 退出时恢复策略；异常路径由辅助进程兜底。

## 13. 分阶段与待确认

### 13.1 建议实施阶段

| 阶段 | 内容 |
|---|---|
| UI-A | 状态模型/Presenter、视觉令牌、基础控件、主窗口重构 |
| UI-B | 设置窗口（常规/熄屏/更新保护/诊断）与设置迁移 |
| UI-C | 首次运行向导、退出/恢复失败对话框、通知与托盘统一 |
| UI-D | 可访问性、DPI、键盘、高对比度、错误状态 |
| UI-E | 深色主题、英文资源、开机启动方案（如需） |

> 1.3.3 已实现 UI-A/B/C/D 的首版浅色中文范围；UI-E 留待后续。§13.2 的默认决策已在 1.1 中采用：不做开机自启、默认最小化、自动保存、浅色中文、保留 3 秒预览。

### 13.2 需要你确认的决策

1. **开机自启**：首版是否明确不做？推荐首版不做，避免登录时 UAC 或高权限 UI；后续单独设计计划任务/服务模式。
2. **主窗口关闭行为**：推荐默认“最小化到任务栏”，保护开启时强制最小化；是否接受？
3. **设置保存**：推荐自动保存（无“应用”按钮），风险操作即时生效；是否接受？
4. **主题/语言**：推荐首版简体中文+浅色，深色/英文作为 Phase 2；是否接受？
5. **“预览覆盖范围 3 秒”**：是否保留为多屏用户的安全预览功能？
6. **主窗口尺寸**：推荐 720×640 DIP、可调整，最小 680×600；是否接受？
7. **产品名称/图标**：继续使用“幕帘 / ScreenCurtain”？
8. **安全提示强度**：首次运行要求勾选“黑屏不是锁屏”；是否接受？

## 14. 实现状态与后续差距

### 14.1 1.1 已实现

- 3 步首次运行向导，UAC 仅在用户点击启用保护后触发。
- 主窗口仪表盘、显示器状态、更新保护五态、快速选项（含熄屏静音）、底栏。

- 统一托盘状态与菜单；熄屏期间不隐藏 `NotifyIcon`，由无边框全屏层覆盖。
- 应用通知在 Dark 期间静默，恢复后合并提示。
- 无边框全屏 + Topmost Guard；系统音频静音/恢复及异常恢复文件。

- 深色主题、开机自启仍为 Phase 2；首版不显示假开关。中英文界面已实现。
- 主窗口/设置窗口目前固定尺寸（DPI 缩放由 WinForms 处理）；可调整尺寸和 100/150/200% 完整视觉验收需在目标桌面继续做。

- 系统安全桌面/关键提示无法覆盖；系统 Toast 的最终层叠行为以真实 Windows 11 验收为准。

这些差距是首版已知取舍，不改变核心熄屏、输入安全、更新保护和静音行为。
